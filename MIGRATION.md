# Безопасный переход

Эта версия НЕ запускает DROP TABLE над старой production базой.

1. Остановите изменения в предыдущей версии, сделайте pg_dump/резервную копию D1/SQLite. Проверьте восстановление backup.
2. До отключения предыдущей версии экспортируйте нужные финансовые данные её владельцам. Автоматического экспорта старой БД в локальный workspace в этой поставке нет; пока это ручной migration step. Не удаляйте старую базу до подтверждённого переноса.
3. Разверните новую версию на НОВОЙ PostgreSQL базе/volume. Compose использует vault_postgres_data, старый postgres_data не трогает.
4. scripts/migrate.mjs прекращает работу, если видит legacy public.users. Никакого автоматического уничтожения персональных таблиц.
5. Новые migrations берутся только из migrations/vault. Старые migrations/postgres и drizzle удалены из текущей поставки; история остаётся в Git. Они не применяются новой версией.
6. Старые OAuth refresh tokens отзовите у Google и удалите старые credentials из инфраструктуры после завершения старого сервиса. Новый код не использует их.

В старом frontend при аудите не обнаружен финансовый IndexedDB/localStorage формат. Demo массивы не переносятся в личный workspace. Первый запуск создаёт пустое локальное состояние по действию пользователя. Если версия нового local schema неизвестна, приложение останавливает запись и показывает ошибку; данные не стираются.

Нельзя утверждать, что старые deployment backups уже не содержат plaintext: они специально сохранены и требуют отдельного решения владельца. Новая целевая база содержит только vaults и публичный каталог.

Workspace v1 обновляется до v2 автоматически с сохранением исходной локальной копии. Не очищайте IndexedDB при ошибке миграции. Старые encrypted backups поддерживаются. SQL 0000_vault.sql не изменён; Drizzle meta baseline описывает уже существующую схему и не создаёт таблицы повторно.
